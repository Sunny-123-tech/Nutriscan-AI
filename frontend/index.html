UNIT-I

Relational Data Model, Constraints, Anomalies & Normalization

Explores relational database schemas, domain/key/entity/referential integrity constraints, and live simulation of Insertion, Deletion, and Modification Anomalies with 3NF/BCNF normalization remedies.

Users Relation (3NF) PK: user_id
  • user_id VARCHAR(36) PRIMARY KEY, NOT NULL
  • email VARCHAR(255) UNIQUE, DOMAIN(email)
  • name VARCHAR(100) NOT NULL
  • age INT CHECK (age BETWEEN 1 AND 120)
  • bmi DECIMAL(4,1) CHECK (bmi > 0)
  • chronic_condition VARCHAR(50) DOMAIN(diabetic, hypertensive...)
Products Relation (3NF) PK: barcode
  • barcode VARCHAR(14) PRIMARY KEY, NOT NULL
  • name VARCHAR(255) NOT NULL
  • brand VARCHAR(100) NOT NULL
  • category VARCHAR(50) NOT NULL
  • sugar_g DECIMAL(5,2) CHECK (sugar_g >= 0)
  • sodium_mg INT CHECK (sodium_mg >= 0)
  • calories_kcal INT CHECK (calories_kcal >= 0)
MealLogs Relation (3NF) PK: log_id
  • log_id VARCHAR(36) PRIMARY KEY, NOT NULL
  • user_id VARCHAR(36) FK ➔ Users(user_id) [ON DELETE CASCADE]
  • product_barcode VARCHAR(14) FK ➔ Products(barcode) [ON DELETE RESTRICT]
  • logged_at TIMESTAMP NOT NULL DEFAULT NOW()
  • servings DECIMAL(3,1) CHECK (servings > 0)

Shared Memory (SMP)

All CPUs share main RAM and disk. Fast bus communication, but limited to 32–64 cores due to memory bus saturation.

Shared Disk (SAN/NAS)

Independent CPUs have private RAM but share centralized SAN storage. Flexible scaling but storage network bandwidth bound.

Shared Nothing (MPP)

Each node owns private CPU, RAM, and Disk. Scales horizontally to thousands of nodes via high-speed interconnect.

Star vs Snowflake Schema Model

Fact Table: Fact_Nutritional_Scans (Measures: sugar, sodium, calories, glycemic load).

Star Schema: Denormalized single-hop dimensions (Dim_Time, Dim_Product, Dim_User, Dim_Store) for fastest read performance.
Snowflake Schema: Normalized hierarchies (Dim_Product ➔ Dim_Subcat ➔ Dim_Category) eliminating dimensional redundancy.
